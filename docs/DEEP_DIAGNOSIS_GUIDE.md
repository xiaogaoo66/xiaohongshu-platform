# 🔬 深度诊断工具使用指南

## 概述

深度诊断工具是一个系统化的诊断系统，用于检查 S3 上传功能中的**隐蔽问题**，而不仅仅是基础配置问题。

## 访问诊断端点

### 端点地址

```
GET /api/upload/deep-diagnosis
```

**无需认证**，方便调试。

### 示例

```bash
curl https://你的后端域名/api/upload/deep-diagnosis
```

## 诊断内容

深度诊断工具会系统性地检查以下 **12 个类别**的问题：

### 1. 环境变量深度检查 ✅
- 检查所有必要的环境变量是否存在
- 验证 Access Key ID 格式（AKIA + 16位字符）
- 验证 Secret Access Key 长度
- 验证 Region 格式
- 验证 Bucket 名称格式

### 2. AWS SDK 配置检查 ✅
- 验证签名版本（必须是 v4）
- 检查路径样式配置
- 验证 SDK 初始化状态

### 3. 预签名URL签名算法检查 ✅
- 验证所有必需的签名参数是否存在
- 检查 Content-Type 是否包含在签名头中
- 验证 URL 中的 Content-Type 参数
- 验证签名算法（AWS4-HMAC-SHA256）
- 检查过期时间设置

### 4. 请求头匹配检查 ✅
- 分析签名头列表
- 检查 Content-Type 是否在签名头中
- 验证大小写敏感性
- 检查前端上传时需要的请求头

### 5. 时间同步检查 ✅
- 检查服务器时间与 AWS 时间的差异
- 验证时间差异是否在允许范围内（5分钟内）
- 识别时间不同步导致的签名验证失败

### 6. 存储桶策略深度检查 ✅
- 检查存储桶策略是否存在
- 验证是否允许 s3:PutObject 操作
- 测试存储桶访问权限
- 检查 IAM 策略与存储桶策略的配合

### 7. CORS配置检查 ✅
- 检查 CORS 规则是否存在
- 验证是否允许 PUT 方法
- 检查允许的来源配置
- 识别 CORS 配置问题

### 8. 区域配置检查 ✅
- 获取存储桶的实际区域
- 对比配置的区域与实际区域
- 识别区域不匹配问题

### 9. URL编码问题检查 ✅
- 测试特殊字符的文件名
- 验证 URL 编码是否正确
- 检查路径分隔符处理

### 10. 实际文件上传测试 ✅
- **直接上传测试**：使用 AWS SDK 直接上传，验证 IAM 权限
- **预签名URL上传测试**：使用预签名URL上传，验证签名和权限
- 自动清理测试文件

### 11. 网络连接检查 ✅
- 测试 S3 端点连接
- 验证网络可达性
- 检查防火墙设置

### 12. 签名版本检查 ✅
- 验证签名算法版本
- 确保使用 AWS4-HMAC-SHA256

## 诊断结果格式

### 响应结构

```json
{
  "summary": {
    "total": 50,
    "passed": 45,
    "failed": 3,
    "warnings": 2
  },
  "results": [
    {
      "category": "预签名URL",
      "test": "签名参数完整性",
      "status": "pass",
      "message": "所有必需的签名参数都存在",
      "details": {
        "allParams": ["X-Amz-Algorithm", "X-Amz-Credential", ...]
      }
    },
    {
      "category": "请求头匹配",
      "test": "Content-Type 签名",
      "status": "fail",
      "message": "Content-Type 未包含在签名头中",
      "details": {
        "signedHeaders": "host",
        "contentType": "image/jpeg"
      },
      "recommendation": "确保 Content-Type 包含在 X-Amz-SignedHeaders 中"
    }
  ],
  "criticalIssues": [
    "Content-Type 未包含在签名头中",
    "区域不匹配"
  ],
  "recommendations": [
    "确保 Content-Type 包含在 X-Amz-SignedHeaders 中",
    "将 AWS_REGION 环境变量更新为 us-east-2"
  ]
}
```

### 状态说明

- **pass** ✅：测试通过，没有问题
- **fail** ❌：测试失败，需要立即修复
- **warning** ⚠️：潜在问题，建议检查

## 常见隐蔽问题

### 1. Content-Type 签名问题

**症状**：预签名URL生成成功，但上传时403

**诊断**：检查 `请求头匹配` 类别中的 `Content-Type 签名` 测试

**解决方案**：
- 确保生成预签名URL时传入 `ContentType` 参数
- 前端上传时必须使用完全相同的 Content-Type
- 不要添加其他请求头

### 2. 区域不匹配

**症状**：配置看起来正确，但上传失败

**诊断**：检查 `区域配置` 类别中的 `区域匹配` 测试

**解决方案**：
- 在 AWS S3 控制台查看存储桶的实际区域
- 更新 `AWS_REGION` 环境变量

### 3. 时间不同步

**症状**：签名验证失败，错误信息不明确

**诊断**：检查 `时间同步` 类别中的 `服务器时间同步` 测试

**解决方案**：
- 确保服务器时间与 AWS 时间同步
- 使用 NTP 同步服务器时间

### 4. 签名参数缺失

**症状**：预签名URL看起来正常，但上传失败

**诊断**：检查 `预签名URL` 类别中的 `签名参数完整性` 测试

**解决方案**：
- 确保使用 `signatureVersion: 'v4'`
- 检查 AWS SDK 配置

### 5. 存储桶策略冲突

**症状**：IAM权限正确，但上传失败

**诊断**：检查 `存储桶策略` 类别中的测试结果

**解决方案**：
- 检查存储桶策略是否明确允许 s3:PutObject
- 确保 IAM 策略和存储桶策略不冲突

## 使用建议

### 1. 定期运行诊断

建议在以下情况运行深度诊断：
- 首次配置 S3 上传功能
- 遇到上传失败问题
- 更新 AWS 配置后
- 部署到新环境前

### 2. 关注关键问题

优先处理 `criticalIssues` 数组中的问题，这些问题会导致上传失败。

### 3. 查看详细信息

每个测试结果都包含 `details` 字段，提供详细的诊断信息，帮助定位问题。

### 4. 遵循建议

`recommendations` 数组提供了具体的修复建议，按照建议操作可以快速解决问题。

## 与基础诊断的区别

| 特性 | 基础诊断 (`/api/upload/diagnose`) | 深度诊断 (`/api/upload/deep-diagnosis`) |
|------|----------------------------------|----------------------------------------|
| 检查范围 | 基础配置（环境变量、连接测试） | 12个类别的深度检查 |
| 检查深度 | 表面检查 | 深入分析签名、权限、配置 |
| 问题定位 | 基础问题 | 隐蔽问题 |
| 测试数量 | ~5个测试 | ~50个测试 |
| 实际上传测试 | ❌ | ✅ |
| 签名分析 | ❌ | ✅ |
| 时间同步检查 | ❌ | ✅ |
| URL编码检查 | ❌ | ✅ |

## 故障排查流程

1. **运行深度诊断**
   ```bash
   curl https://你的后端域名/api/upload/deep-diagnosis
   ```

2. **查看摘要**
   - 检查 `summary` 中的失败和警告数量
   - 查看 `criticalIssues` 数组

3. **分析结果**
   - 按类别查看 `results` 数组
   - 重点关注 `status: "fail"` 的测试

4. **修复问题**
   - 按照 `recommendations` 中的建议修复
   - 参考 `details` 中的详细信息

5. **重新测试**
   - 修复后重新运行诊断
   - 确认所有测试通过

## 注意事项

1. **实际上传测试**会创建测试文件，诊断工具会自动清理，但如果诊断中断，可能需要手动清理
2. **网络连接测试**可能需要几秒钟，请耐心等待
3. **时间同步检查**依赖于服务器时间，确保服务器时间准确
4. 某些测试可能需要特定的 AWS 权限，如果测试失败，检查 IAM 权限

## 技术支持

如果深度诊断工具无法解决问题，请：
1. 保存完整的诊断结果
2. 检查 AWS CloudTrail 日志
3. 查看浏览器网络请求详情
4. 联系技术支持并提供诊断结果
